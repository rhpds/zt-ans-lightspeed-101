== はじめに - セットアップ

[IMPORTANT]
====
**このラボに関する重要な注意点**

IBM watsonx Code Assistantモデルは継続的に更新され、改善されています。その結果、モデルの更新により、このラボで説明されている特定のタスク生成の課題が、説明どおりに機能しない場合があります。これは予期される動作です。

**このラボの主な目的は、Ansible Lightspeedの主要な機能、特に以下について理解を深めることです。**

* **プレイブック生成** - 自然言語のプロンプトからプレイブック全体を生成する
* **タスク生成** - 個別のタスク、または複数のタスクを一度に生成する
* **トレーニングの一致** - AIサジェスチョンの透明性を理解する
* **ベストプラクティス** - LightspeedがどのようにAnsibleのベストプラクティスを取り入れているかを学ぶ

**特定のプロンプトが期待どおりにサジェスチョンを生成しない場合:**

* タスク生成ではなく**プレイブック生成**を試す（Ansibleアイコンをクリック → **Generate a playbook**ボタンをクリックし、プロンプトを入力、アウトラインをレビューしてからContinueをクリックします）
* 最適なサジェスチョンを得るために、さまざまなプロンプトのバリエーションを試す
* 複雑なマルチタスクのプロンプトを、個別のシングルのタスクのプロンプトに単純化する
* 学習目標は変わりません。AIアシストによるAnsible開発の取り組み方を理解することです。
====

この課題は、IBM watsonx Code AssistantとのAnsible Lightspeed商用サービスの**プレイグラウンドデモ環境**を提供します。これは、ご自身のワークフローに最適なユースケースを試すためのものです。

すべてのデモコンテンツは、link:[https://github.com/ansible/ansible-lightspeed-demos](https://github.com/ansible/ansible-lightspeed-demos)[Ansible Lightspeed demosリポジトリ]で入手できます。

[NOTE]
====
**プレイグラウンド環境:** これは、学習したすべてのAnsible Lightspeed機能を自由に探索できるプレイグラウンドです。以前のモジュールからのすべてのデモプレイブックがここで利用できます。

**認証情報:**
* **Ansible Automation Platform:** `admin` / `ansible123!`
* **Gitea:** `gitea` / `gitea`
* **AWS/Azure認証情報:** **AWS/Azure**タブで利用可能
====

|===

## デモの実行方法

すべての手順は、link:[https://github.com/ansible/ansible-lightspeed-demos](https://github.com/ansible/ansible-lightspeed-demos)[リポジトリのREADME]でも入手できます。

### VS Codeでデモを選択する

1.   ラボ環境の上部にある**VS Code**タブをクリックして、**VS Codeを開きます**。

[IMPORTANT]
====
**新しいブラウザタブで作業:** Ansible Lightspeedの機能を最大限に活用するには、インラインの埋め込みウィンドウを使用するのではなく、**VS Codeタブをクリックして新しいブラウザタブで開いてください**。
====

2.   **デモプレイブックを参照します。**
+
    a. VS Codeの左側にある**Explorer**アイコン（2つのドキュメントが重なっているように見えます）をクリックします。
+
    b. **playbooks**フォルダを展開して、利用可能なすべてのデモを確認します。
       * **playbooks/infra/install_cockpit/** - Cockpitデプロイメントデモ
       * **playbooks/infra/install_pgsql_and_pgadmin/** - PostgreSQLおよびPGAdminデモ
       * **playbooks/cloud/aws/** - AWS EC2プロビジョニングデモ
       * **playbooks/cloud/azure/** - Azure VMプロビジョニングデモ

3.   **デモプレイブックを開きます。**
+
    a. いずれかのデモフォルダ（例: `playbooks/infra/install_cockpit/`）に移動します。
+
    b. 2つのプレイブックが表示されます。
       * **demo_<playbook_name>.yml** - Lightspeedのプロンプトを含む開始点
       * **solution_<playbook_name>.yml** - 参照用の完全な解決策
+
    c. `demo_<playbook_name>.yml` ファイルを開いてデモを開始します。

### プレイブックを実行する

`demo_*.yml` プレイブックは、**Automation Controller**または **`ansible-navigator`** のいずれかを使用して実行できます。

#### オプション1: Automation Controllerの使用

1.   **プレイブックをGitにコミットしてプッシュします。**
+
    a. VS Codeの左側にある**Source Control**アイコン（円が付いたブランチ）をクリックします。
+
    b. 変更したファイルにカーソルを合わせ、**+**アイコンをクリックしてステージングします。
+
    c. 「Message」ボックスにコミットメッセージを入力します。
+
    d. **Commit**ボタン（チェックマークアイコン）をクリックします。
+
    e. **Sync Changes**をクリックしてGitにプッシュします。

2.   **対応するジョブテンプレートを実行します。**
+
    a. 上部にある**Ansible Automation Platform**タブをクリックします。
+
    b. プロンプトが表示されたら `admin` / `ansible123!` でログインします。
+
    c. 左側のサイドバーで**Resources** → **Templates**をクリックします。
+
    d. デモに対応するジョブテンプレートを見つけます。
+
[cols="1a,1a", options="header"]
|===
| ジョブテンプレート名 | デモプレイブック
| Deploy monitoring | `demo_install_cockpit.yml`
| Deploy PostgreSQL and PG Admin | `demo_install_pgsql_pgadmin.yml`
| Provision EC2 instance | `demo_provision_ec2_instance.yml`
| Provision Azure VM | `demo_provision_azure_vm.yml`
|===
+
    e. テンプレートの横にある**起動アイコン**（🚀）をクリックします。
+
    f. ジョブが正常に完了するまで待ちます。

#### オプション2: ansible-navigatorの使用

1.   **VS Codeでターミナルを開きます。**
+
    a. **VS Code**タブにいることを確認します。
+
    b. 上部のメニューから**Terminal** → **New Terminal**をクリックします。
+
    c. ターミナルパネルが下部に開きます。

2.   **デモフォルダに移動します。**
+
    ターミナルで、次のコマンドを入力します（選択したデモに合わせて調整します）。
+
[source,bash]
----
cd playbooks/infra/install_cockpit
----

3.   **プレイブックを実行します。**
+
    コマンドを入力し、`ENTER` を押します。
+
[source,bash]
----
ansible-navigator run demo_install_cockpit.yml
----
+
    完了したら `ESC` キーを押してプロンプトに戻ります。

## ヘルプと追加情報

### Ansible Lightspeedの機能

このプレイグラウンドでAnsible Lightspeedを使用する方法は主に**2つ**あります。

#### 方法1: プレイブック生成（推奨）

自然言語を使用して、プレイブック全体を一から生成します。

1.   **プレイブック生成にアクセスします。**
+
    a. VS Codeの左側にある**Ansible**アイコン（「A」のように見えます）をクリックします。
+
    b. **Ansible Lightspeed**セクションで、**Generate a playbook**ボタンをクリックします。
+
       * 注: このボタンは、ログインしてトライアルを正常にアクティベートした後にのみ表示されます。

2.   **プロンプトを入力します。**
+
    a. 「Describe what you want to achieve in natural language（自然言語で達成したいことを記述してください）」というラベルの付いたテキストボックスがある新しい画面が開きます。
+
    b. プレイブックに実行させたいことの説明を入力します。
+
    c. **Analyze**ボタンをクリックします。

[TIP]
====
**効果的なプロンプトの書き方:**

* 「Generate a playbook」や「Create a playbook」のようなフレーズを含める**必要はありません** - AIはプレイブックを作成していることを知っています
* プレイブックに実行させたいことを平易な言葉で記述するだけです
* 達成したいタスクについて具体的に記述します

**プロンプトの例:**

* `for rhel hosts with sudo, install and configure Apache web server with SSL enabled` (sudoを持つrhelホスト用に、SSLを有効にしてApacheウェブサーバーをインストールおよび設定する)
* `configure PostgreSQL database on CentOS hosts and create a backup user` (CentOSホストでPostgreSQLデータベースを設定し、バックアップユーザーを作成する)

インターフェースには、インスピレーションとして使用できるプロンプトの例も表示されます。
====

3.   **アウトラインのレビューと編集を行います。**
+
    a. Analyzeをクリックすると、Ansible Lightspeedがプレイブックの**アウトライン**を表示します。
+
    b. アウトラインには、プレイブックの提案された手順が表示されます。
+
    c. **アウトラインは編集可能**です - 要件に合わせて必要に応じて手順を変更できます。
+
    d. アウトラインをレビューし、必要に応じて調整を加えます。

4.   **プレイブックを生成します。**
+
    a. アウトラインに満足したら、**Continue**ボタンをクリックします。
+
    b. Ansible Lightspeedがアウトラインに基づいて完全なプレイブックを生成します。

5.   **プレイブックを保存します。**
+
    a. プレイブックはエディターに「Untitled」として開きます。
+
    b. `CTRL+S` (Windows/Linux) または `CMD+S` (Mac) を押してファイルを保存します。
+
    c. プレイブックに`.yml`で終わるわかりやすい名前を付けます（例: `install_apache.yml`、`configure_database.yml`）。
+
    d. 保存場所を選択します（整理のために `playbooks/` ディレクトリが推奨されます）。
+
    e. **注:** デモプレイブックと同じ名前（例: `demo_install_cockpit.yml`）で保存した場合、AAPの既存のジョブテンプレートを使用できます。そうでない場合は、新しいジョブテンプレートを作成する必要があります。

#### 方法2: タスク生成

既存のプレイブック内で個別のタスクを生成します。

1.   **単一タスク:**
+
    a. `#` を削除してタスク名行のコメントアウトを解除します（または `CTRL+/` / `CMD+/` を押します）。
+
    b. カーソルをタスク名行の末尾に置きます。
+
    c. `ENTER` を押して新しい行を作成します。
+
    d. Lightspeedが**グレーのテキストでサジェスチョン**を表示します。
+
    e. `TAB` を押してサジェスチョンを受け入れます。

2.   **マルチタスク:**
+
    a. `&` で区切られた複数のタスクを含むコメント行を見つけます。
+
    b. **コメントアウトを解除しないでください** - `#` はそのままにしておきます。
+
    c. カーソルを行の末尾に置きます。
+
    d. `ENTER` を押して新しい行を作成します。
+
    e. Lightspeedが**複数のタスク**を生成します。
+
    f. `TAB` を押してすべてのサジェスチョンを受け入れます。

### 解決策プレイブック

ヘルプが必要な場合や作業内容を比較したい場合は、各デモフォルダで `solution_` プレフィックスが付いた解決策プレイブック（例: `solution_install_cockpit.yml`）を利用できます。
